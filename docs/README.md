## Plans, reports, and roadmaps

`plans/` contains bounded implementation requests. A plan describes intended work and must not be read as evidence that the work exists.

`reports/` records completed runs and their established evidence, limitations, validation results, and next pressure.

`roadmaps/` describes longer dependency order and destination. Roadmap batch numbers are planning bands rather than completion claims.
